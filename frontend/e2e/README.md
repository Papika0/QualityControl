# e2e — დავალებების შემოწმება

ორი დამოუკიდებელი კრებული. არცერთი არ არის `npm test`-ში: Playwright განზრახ
არ არის `package.json`-ში, რომ `npm install` ბრაუზერს არ ჩამოტვირთავდეს.

## `api.ts` — ლოგიკა, ბრაუზერის გარეშე

მართავს ნამდვილ `api.tasks`-ს Node-ში. `idb.ts` `indexedDB`-ის არარსებობისას
`MemoryBackend`-ზე გადადის, ამიტომ seed + client მთლიანად, უცვლელად მუშაობს —
იგივე კოდის გზა, რასაც UI იძახებს.

```bash
cd frontend
cp e2e/api.ts ./drive.ts && npx tsx ./drive.ts; rm drive.ts
```
(`tsx` `@/*` alias-ს მხოლოდ პროექტის ფესვიდან წყვეტს — აქედან კოპირება.)

ფარავს: ხილვადობას როლების ჭრილში, `req→ახალი` ბარიერებს, ready/confirm
handshake-ს, `techOk`-ის ბარიერს, ქვე-დავალებებს, ისტორიას.

## `tasks.mjs` — ნამდვილი ბრაუზერი

```bash
npm i -D playwright && npx playwright install chromium   # ერთხელ
npm run dev                                              # ცალკე ტერმინალში
node e2e/tasks.mjs http://localhost:5173 ./e2e/shots
```

ფარავს: დაფას 8 როლისთვის, რესპონსივს 3 ზომაზე (გვერდი გვერდულად არ სქროლავს,
5 სვეტი ერთ რიგში), ტიკეტის განლაგებას (ტელეფონზე ეწყობა, დესკტოპზე 2 სვეტი),
სრულ workflow-ს დაწკაპუნებით და შექმნის დიალოგს. სქრინშოთები `shots/`-ში.

### ორი მახე, რომლებმაც უკვე დაგვაბრკოლა

- **თითო Playwright კონტექსტს თავისი IndexedDB აქვს.** ერთი კონტექსტი მთელ
  გაშვებაზე — თორემ ყოველი ნაბიჯი ახლად დათესილ ბაზას იღებს და წინას ჩუმად
  აუქმებს. როლი localStorage-ის გადაწერით და reload-ით იცვლება.
- **`text=დავალებები` გვერდითა მენიუსაც ხვდება.** დაელოდე
  `[data-testid="task-board"]`-ს — 3 პროექტის დათესვას წამები სჭირდება.
